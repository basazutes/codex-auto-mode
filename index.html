Codex auto mode, in one page

In today’s OpenAI Codex CLI, auto mode is one of three built-in presets. It lets Codex read and edit files in the current workspace and run commands, and asks you before it touches files outside the workspace or uses the internet. The legacy --full-auto flag is gone; this page shows what to use instead.

TL;DR

  • auto = sandbox: workspace-write + approval_policy: on-request. Labeled “Default” in Codex. source
  • Three built-in presets: read-only, auto, full-access. source
  • --full-auto was removed in Codex v0.147.0 (2026-08-07). Use --sandbox workspace-write. source
  • The corresponding global flag for “skip every prompt” is --dangerously-bypass-approvals-and-sandbox. Use it only in a disposable VM or container. source

The three presets

Codex ships three built-in approval presets. Each pairs an approval policy (when it asks you) with a permission profile (what it can touch without asking).

read-only

approval: on-request · profile: read-only

Codex can read files in the current workspace. It asks you to edit files or access the internet.

auto Default

approval: on-request · sandbox: workspace-write

Codex can read and edit files in the current workspace, and run commands. Approval is required to access the internet or edit other files. Identical to Agent mode.

full-access

approval: never · profile: disabled

Codex can edit files outside this workspace and access the internet without asking. Use with caution.

Source: codex-rs/utils/approval-presets/src/lib.rs.

How to turn auto mode on

From the command line, one off

codex --sandbox workspace-write --approval-mode on-request
# or the short form of --sandbox:
codex -s workspace-write

In ~/.codex/config.toml, as the default

sandbox_mode    = "workspace-write"
approval_policy = "on-request"

Both keys accept the kebab-case values shown in config_types.rs: read-only, workspace-write, danger-full-access for the sandbox; on-request, never for the approval policy.

Migrating from --full-auto

If you came here because codex --full-auto or full-auto = true stopped working, the flag was removed in v0.147.0. Two common mappings:

OldNewWhat changes
codex --full-auto codex --sandbox workspace-write Same effective behaviour: edits inside the workspace, asks for the internet and for files outside.
codex --full-auto --dangerously-auto-approve-everything (old variants) codex --dangerously-bypass-approvals-and-sandbox No sandbox, no prompts. Only in a disposable VM or container.

Source for the removal: openai/codex#2138 — “--full-auto was removed in Codex 0.147.0 (7 August 2026). The release note says to use --sandbox workspace-write instead.”

Which preset should you use

  • You’re reviewing someone else’s repo, or you don’t want file writes yet. read-only.
  • You’re doing normal coding in a repo you trust. auto. This is the default and matches the old --full-auto expectation.
  • You’re running Codex in a disposable VM or container where nothing on the host matters. full-access, or use --dangerously-bypass-approvals-and-sandbox for a one-off.

danger-full-access / --dangerously-bypass-approvals-and-sandbox turn off the sandbox and the approval prompts at the same time. Codex can delete files anywhere you have access to, and can make network calls without asking. Use it only when the environment is disposable.

Short FAQ

Does auto mode skip all prompts?

No. It skips approval for writes inside the workspace and for running commands. It still asks before editing files outside the workspace or using the internet.

Is “Agent mode” the same as auto?

Yes. The preset’s own description says “Identical to Agent mode.” source

Is there a Codex YOLO mode?

Not under that name. The closest thing is the full-access preset, or the one-off flag --dangerously-bypass-approvals-and-sandbox, which removes both the sandbox and every approval prompt. Use it only in a disposable VM or container. source

How do I make Codex auto-approve everything?

Set --approval-mode never (or approval_policy = "never" in config.toml). On its own that only stops the prompts; what Codex may touch still depends on the sandbox. Pair it with workspace-write to keep edits inside the repo, or with danger-full-access to lift every limit. source

Codex says approval_policy = "untrusted" is no longer supported

Remove that line from ~/.codex/config.toml. The only approval values left are on-request and never; on-request is the closest match to the old behaviour. source

What’s the difference between --sandbox and --approval-mode?

--sandbox controls what Codex can touch without asking. --approval-mode controls when it stops to ask you. The preset auto is just the common pairing of workspace-write and on-request.

Where do I set this permanently?

In ~/.codex/config.toml. The CLI flag wins for one session.

I’m outside a git repo and Codex refuses to run.

Add --skip-git-repo-check. Flag defined in codex-rs/exec/src/cli.rs.
